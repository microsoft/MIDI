  1. Where it came from: the configuration's name, the PC it was shared from, the date and the note.
  2. Into the configuration in use, or kept apart as a new one. Adding keeps everything already there, so the line under it is true by default. Kept apart skips the add-or-replace choices, but still fixes clashing names.
  3. Each part has a choice. Device names and pictures: Add to mine, Replace mine or Don't import (options), plus Keep mine or Use the package's for devices that already have your names. Replace lists exactly what it removes (replace). Loopbacks, network, RTP-MIDI and Bluetooth: Add to mine or Don't import. Other settings: Keep mine or Use the package's.
  4. Every row says what will happen, in the same place. Devices that aren't plugged in still come across. If one can't be found later, today's "Some saved settings have no matching device" banner offers Review them.
  5. A loopback whose name is taken here isn't added, and says why. Ticking the box adds it under a free name instead.
  6. A network host named after the other PC takes this PC's name, ticked by default, so two PCs never claim the same name and identity. A taken host name works like a taken loopback name. A host tied to a missing Wi-Fi or Ethernet adapter uses any adapter here.
  7. The customer's own synthesizer mode and port names are kept unless they choose the package's. Choosing the package's port names adds a warning to this line and to the footer, before Import is chosen (restart).
  8. Nothing changes until Import, and the configuration is backed up first, pictures and settings included. Import writes the configuration file, so the MIDI service always restarts to use it. The next page offers the restart and Undo this import.
