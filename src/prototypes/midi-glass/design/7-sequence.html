Why this is a list and not a script. Layouts get shared on forums, so a layout file is untrusted input from a stranger. Putting a general-purpose script engine behind a downloaded file would make a sequencer into a code delivery mechanism, and it would drag a large runtime into a tool that has to start instantly and run with no network. A fixed set of steps covers what people actually build — recall a patch, arpeggiate, stage a crossfade, jump to a page — and every step is inspectable, localizable and readable by a screen reader.

If it ever needs more, the right escape hatch is a tiny expression for value mapping only (value * 0.5 + 0.25), with no loops, no I/O and no file access. That is a few hundred lines and cannot be turned into a payload. Recommendation: no JavaScript engine, in this version or later.

Waits never block the surface. Each running sequence is a small scheduled state machine on the MIDI clock, not a sleeping thread, so twenty buttons can be mid-sequence while a fader still moves at full rate.
